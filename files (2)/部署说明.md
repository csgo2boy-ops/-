# 发布跟读笔记

这个文件夹里的东西合起来就是完整的网站。往下照做就能上线。

## 文件都是干什么的

| 文件 | 作用 |
|---|---|
| `index.html` | 整个应用，所有功能都在这一个文件里 |
| `sw.js` | 让网站能离线打开、能提示更新 |
| `manifest.webmanifest` | 告诉手机这是个可以装到桌面的应用 |
| `icon-*.png` `apple-touch-icon.png` `favicon-32.png` | 桌面图标 |

**这几个文件必须放在同一层目录**，名字不要改。改了名字会互相找不到。

---

## 第一步：先在自己电脑上试一遍

在这个文件夹里，地址栏输入 `cmd` 回车，然后：

```
npx serve
```

打开它给出的 `http://localhost:3000`。这一步是为了确认文件都齐、能跑起来。

Service Worker 在 `localhost` 下也能工作，所以离线和更新提示都能在这里测。

---

## 第二步：上线

选一个，都免费，都自带 https（麦克风必须要 https 才能用）。

### 方式 A：Cloudflare Pages（推荐长期用）

1. 注册 [dash.cloudflare.com](https://dash.cloudflare.com)
2. 左侧找到 **Workers & Pages** → **Create** → **Pages** → **Upload assets**
3. 把整个文件夹拖进去，起个项目名
4. 几十秒后拿到 `你的项目名.pages.dev` 的网址

以后要更新，回到同一个项目再上传一次新文件即可。

### 方式 B：GitHub Pages（会用 Git 的话最省心）

1. 在 GitHub 建一个仓库，把这些文件传上去（放在仓库根目录）
2. 仓库 **Settings** → **Pages** → Source 选 `Deploy from a branch`，分支选 `main`，目录选 `/ (root)`
3. 等一两分钟，拿到 `你的用户名.github.io/仓库名/` 的网址

以后改代码 push 上去就自动更新。

### 方式 C：Netlify

1. 注册后进 [app.netlify.com](https://app.netlify.com)
2. **Add new site** → **Deploy manually**，把文件夹拖进去

> ⚠️ 不要用之前那种 **Netlify Drop** 一次性拖拽。那种方式每次都给一个新网址，
> 而浏览器是按网址存数据的 —— 换了网址，用户之前录的东西就全看不见了。
> 正式发布一定要用一个固定的网址。

---

## 第三步：换成自己的域名（可选）

一个域名一年大约 10 到 15 美元。Cloudflare Registrar 是按成本价卖的，没有加价。

买好后在托管平台的设置里找 **Custom domain**，按提示填一下就行。

**换域名前想清楚**：浏览器按域名隔离数据。如果已经有人在旧网址上录了东西，
换域名之后他们要先在旧网址导出备份，再到新网址导入。所以域名尽早定下来。

## 上线后自己验一遍

用手机打开网址，检查这几项：

- [ ] 能录音（会弹出麦克风权限请求）
- [ ] 贴一个 YouTube 链接，视频能嵌进来播放
- [ ] Safari 里点分享 → 「加入主畫面」，桌面出现图标
- [ ] 从桌面图标打开，是全屏的，没有浏览器地址栏
- [ ] 开飞行模式再打开，界面还能出来（本地音频还能听，YouTube 自然不行）

---

## 以后怎么更新

改完 `index.html` 之后，**把 `sw.js` 里的版本号改一下**：

```js
const VERSION = "v1";     // 改成 "v2"、"v3" ……
```

不改版本号的话，老用户的浏览器可能继续用缓存里的旧版本。

改完重新部署。用户下次打开时，页面顶部会出现「有新版本 / 刷新启用」的提示条。

## 用户数据的事

**数据全部在用户自己的浏览器里，你这边没有任何服务器，也拿不到任何人的录音。**

这意味着：

- 你不用管服务器、不用管数据库、不用管备份，成本是零
- 但用户清理浏览器数据就会全丢，而且你帮不上忙

应用里已经做了三件事来兜底：首次打开会弹出说明讲清这一点；
超过七天没备份且录音超过 8 段时会提醒去备份；备份和导入都是一个按钮的事。

如果以后真的想做云端同步，那就是另一个量级的工程了 —— 要有账号、有服务器、有存储费用，
还要认真处理隐私。现在这个形态的好处正是没有这些负担。

---

## 需要注意的两条线

**不要在网站里预置任何歌词或 LRC 文件。** 就算只是想给个示范，也用自己写的句子。
现在这个设计里，内容全部由用户自己导入并保存在自己设备上，你提供的是工具而不是内容，
这个位置是清楚的，别把它弄模糊了。

**不要加"下载 YouTube 音频"这类功能。** 那违反 YouTube 的服务条款，性质跟现在完全不同。
目前用官方的嵌入播放器是它明确允许的方式。

（以上是常识层面的提醒，不构成法律意见。如果打算商业化，找专业人士看一眼更稳妥。）
